## Что это такое

Это **не** обычный трекер расходов («записал трату — увидел пирог»).

Это математическая модель одного человека и его денег, где:

- **Личные деньги, BTC и склад комплектующих** — части одного капитала;
- **Компьютер на сборке** — не «список деталей», а капитал в форме железа: деньги не исчезли, они превратились в товар;
- **Каждая операция мастерской** (закупка → сборка → продажа) **автоматически** отражается в финансах — ничего не надо сводить руками;
- Программа показывает **последствия решений до того, как они приняты** («если куплю — запас хода упадёт с 21 до 13 дней»).

Отвечает на 5 вопросов за 10 секунд:

1. Сколько у меня капитала и сколько из него живых денег?
2. Сколько я могу безопасно потратить / отложить прямо сейчас?
3. Сколько заморожено в железе и в незавершённых сборках?
4. Что будет, если я куплю / продам / соберу?
5. Какая сборка из того, что на складе, даст максимум прибыли?

## Главный принцип

> **Система никогда не решает за пользователя.**
> Она показывает данные, формулы и последствия. Решение принимает человек.

В интерфейсе нет и не будет: «тебе нельзя», «нужно продать», «рекомендую купить».
Есть только: «при сценарии X результат Y», «запас хода изменится с A на B».

## Возможности

### Финансы (личный контур)
- Счета: карта, наличные, накопительный, касса бизнеса. Любой счёт можно пометить **«арестован»** — он будет виден, но исключён из доступных денег.
- Операции: доход / расход / перевод. **Перевод ≠ расход** — перемещение денег между карманами не считается тратой.
- **Потоки дохода** с тремя уровнями надёжности:
  - `GUARANTEED` — точно будет (зарплата) — считается живыми деньгами;
  - `EXPECTED` — скорее будет (продажи ПК) — показывается отдельной серой строкой, в доступные деньги **не входит**;
  - `POSSIBLE` — может быть — в расчётах не участвует.
- **Safe-to-Spend** — сколько можно потратить, не сломав план до зарплаты.
- **Safe-to-Save** — сколько можно отложить (сверх несгораемого резерва).
- **Runway (запас хода)** — на сколько дней хватит, если доходы прекратятся сегодня. Два варианта: минимальный и обычный.
- **Net Worth в двух разрезах** — минус «живые» долги и минус вообще все долги.
- **«ЧТО БУДЕТ, ЕСЛИ...»** — симулятор последствий без траты денег.

### Мастерская (бизнес-контур)
- **Закупки**: позиции падают на склад как отдельные лоты, сумма позиций = чек.
- **Склад**: каждая деталь — отдельный объект (цена, состояние, продавец).
- **Конфигуратор**: выбираешь детали → программа проверяет совместимость (сокет, тип памяти, мощность БП, длина видеокарты, высота кулера, порты...) и показывает 🟢 / 🟡 / 🔴.
- Есть 🔴 → кнопку «собрать» заблокирует. Это защита от ошибок, а не запрет — несоответствия видны и объяснены.
- **Сборки**: себестоимость считается автоматически из цен закупки деталей. Целевая цена → мгновенно: прибыль, маржа, ROI.
- **Продажа одной кнопкой**: детали → «продано», выручка → в кассу бизнеса, прибыль → признана, склад → пересчитан. Всё атомарно, одной операцией.
- **Разборка**: детали вернутся на склад, деньги вернутся из «незавершёнки».
- Экономика месяца: выручка, прибыль, количество проданных ПК.

### Связка (то, ради чего всё затевалось)
Каждая операция мастерской **сама** создаёт бухгалтерскую проводку в общей книге:
закупил детали → деньги перетекли в «Склад»; собрал → из «Склада» в «Незавершёнку»;
продал → выручка в «Кассу», себестоимость списана, прибыль признана.
Дашборд финансов **никогда не пересчитывается вручную** — он читает книгу учёта.

### Настройки
- Начальный склад (детали, которые уже есть — без фальшивых трат).
- Параметры модели: размер резерва, минимальная стоимость жизни.
- BTC (ручной ввод, watch-only — программа никогда не попросит seed-фразу).
- Экспорт / импорт JSON, «чистый лист», возврат демо-данных.

## Как работает связка

Пример на цифрах демо-данных:

```text
Ты делаешь в «Мастерской»          Программа делает в «Финансах»
─────────────────────────          ─────────────────────────────
Закупил детали на 2 500 ₽   →      Склад +2 500 / Карта −2 500
                                   (это НЕ расход — деньги стали товаром)
Собрал ПК #001              →      Сборка(WIP) +5 800 / Склад −5 800
                                   (капитал сменил форму: детали → готовый ПК)
Продал за 9 990 ₽           →      Касса +9 990 / Сборка −5 800 / Прибыль −4 190
                                   (себестоимость вернулась, заработано 4 190)
Вывел 5 000 себе            →      Личная карта +5 000 / Касса −5 000
                                   (внутренний переезд, не доход)
```

Дашборд после продажи пересчитывается **сам**: капитал вырос ровно на прибыль,
касса пополнилась, «Заморожено в железе» уменьшилось. Твоих действий — ноль.

## Быстрый старт с нуля (Windows)

### 1. Установить Node.js
Сайт **nodejs.org** → версия **LTS** → установить (везде «Далее»).
Проверка: открыть cmd (Win+R → `cmd` → Enter) → `node -v` — должна показать версию.

### 2. Установить VS Code
Сайт **code.visualstudio.com** → установить (галочки «Добавить в PATH» и контекстное меню — включить).

### 3. Создать проект

```bash
cd C:\Users\%USERNAME%\Desktop
git clone https://github.com/ТВОЙ_ЛОГИН/capital-os.git
cd capital-os
```

*(Если репозитория ещё нет — склонируй этот или создай файлы по структуре из раздела «Структура проекта».)*

### 4. Запустить

```bash
npm install   # один раз, 1–3 минуты
npm run dev
```

Открой адрес из терминала: **http://localhost:5173** (Ctrl+клик по ссылке).
Если порт другой (5174 и т.д.) — открывай тот, что написан у тебя.

**Важно:** сервер живёт, пока открыто окно терминала. Закрыл → сайт «умер» → снова `npm run dev`.
Это нормальный режим разработки. Постоянная версия — после публикации на GitHub Pages (см. ниже).

### 5. Проверить тесты (по желанию)

```bash
npm test
```

Все тесты зелёные = математика ядра работает правильно (эталонные кейсы: «5 800 → 9 990 → ROI 72.2%» и другие).

## Первое включение: заводим свои данные

При самом первом запуске программа загрузит **демо-данные** (пример с ПК #001) — чтобы было что потрогать.
Поиграйся, потом начни с чистого листа:

1. **Настройки → «Начать с чистого листа»** — удалит всё, включая демо.
2. **Настройки → «Параметры модели»**:
   - *Резерв (мес)* = 1 (потом можно поднять до 3–6);
   - *Мин. жизнь ₽/мес* — сколько тебе минимально нужно в месяц (еда, жильё, связь, транспорт). **Самая важная цифра** — от неё считается запас хода. Не уверен — введи примерно, уточнишь позже.
3. **BTC** — есть крипта: введи количество сатоши и цену. Нет — пропускай.
4. **Финансы → «Добавить счёт»**:
   - личная карта (остаток — сколько там сейчас реально),
   - наличные,
   - **Касса бизнеса** (начни с 0),
   - счёт под арестом — галочка «арестован».
5. **Финансы → «Потоки дохода»**:
   - зарплата → `GUARANTEED`, сумма, день выплаты;
   - непостоянный доход (заказы) → `EXPECTED` — программа покажет его «вероятным потоком» и не посчитает живыми деньгами.
6. **Финансы → «Обязательства»**:
   - обычные долги — сумма, платёж в месяц, день;
   - кредиты в процедуре банкротства — галочка **«в процедуре»**: будут видны в Net Worth (полный), но не сломают ежедневные расчёты.
7. **Настройки → «Начальный склад»** — детали, которые уже лежат дома (цена — сколько заплатил или честная оценка).
8. **Настройки → «Экспорт JSON»** — сделай первый бэкап прямо сейчас. Привычка на всё время использования.

## Экраны программы

### Дашборд
Главный экран. Сверху — капитал (живые деньги / арестованные / BTC / железо / общий).
Середина — «можно безопасно потратить», «можно отложить», вероятный поток, запас хода.
Ниже — блок мастерской (касса, прибыль месяца, готовые сборки) и лента ближайших событий (доходы, платежи, сборки, ждущие покупателя).
Кнопки: **«ЧТО БУДЕТ, ЕСЛИ...»**, переход в мастерскую.

### Финансы
Счета с балансами · форма новой операции (доход / расход / перевод) · потоки дохода · обязательства.
Сюда ходишь каждый день на 10 секунд: что-то получил/потратил → записал.

### Мастерская
Три вкладки: **Склад/Сборки** (текущее состояние, продажа, разборка) · **+ ЗАКУПКА** (новые детали) · **КОНФИГУРАТОР** (выбор деталей, живая проверка совместимости, создание сборки).

### Настройки
Параметры модели · BTC · начальный склад · экспорт/импорт/сброс.

## Ежедневный сценарий использования

**Правило одной привычки:**

> Что-то получил или потратил → «Финансы» → операция (10 секунд).
> Купил железо → «Мастерская» → «+ ЗАКУПКА». Собрал → «Конфигуратор». Продал → «ПРОДАНО».

Всё остальное — капитал, запас хода, прибыль, склад — программа пересчитает сама.

**Раз в неделю (2 минуты):**
1. «Настройки» → «Экспорт JSON» → файл в папку бэкапов.
2. Взгляд на дашборд: капитал растёт или падает? Запас хода растёт? Что висит в железе?

**Раз в месяц:** сверить балансы счетов с реальностью (банк-приложение vs программа). Расхождение → операция «Расход/Доход» с пометкой «корректировка».

## Как это устроено внутри

(Раздел для любопытных — пользоваться программой это знать не обязательно.)

**Двойная запись.** Каждая операция — это проводка: сумма уходит с одного счёта и приходит на другой. Сумма всех «ног» каждой операции всегда равна нулю. Если где-то ошибка — балансы не сойдутся, и программа покажет баннер «⚠ Сверка».

**Виртуальные счета.** Кроме твоих счетов (карта, наличные...) в книге есть служебные: `Склад`, `Незавершёнка (WIP)`, `Прибыль (PNL)`, `Капитал владельца`. Именно через них мастерская «разговаривает» с финансами. Баланс `Склада` = стоимость лежащих деталей, баланс `WIP` = стоимость незавершённых сборок, минус баланс `PNL` = накопленная прибыль. Всё считается из проводок — одного источника правды.

**Целостность.** Продажа ПК = одна транзакция базы данных: статусы деталей, статус сборки, проводки. Если что-то оборвётся посередине — ничего не «порвется», откатится целиком.

**Деньги — целые числа (копейки), BTC — сатоши.** Никаких дробей внутри расчётов — исключает ошибки округления.

**Все коэффициенты — видимые настройки** (0.75 для EXPECTED, размер резерва и т.д.), а не спрятанные константы. Программа не должна «врать молча».

## Данные и бэкапы — ВАЖНО

**Без облака:** данные хранятся в браузере конкретного устройства (IndexedDB) и не покидают его.
- Открыл без подключения на телефоне → там своё отдельное хранилище.
- Очистил данные сайта в браузере → стёр базу.

Если включена синхронизация Supabase, копия всех таблиц приложения хранится в выбранном облачном проекте. Подробности и настройка — в следующем разделе.

**Резервная копия всё равно нужна**, даже при включённой синхронизации:

1. **Раз в неделю:** Настройки → «Экспорт JSON» → один файл со всеми данными → папка бэкапов (можно в облачный диск — это просто файл, экспорт это допустимо).
2. **Перенос на другое устройство:** экспорт тут → Настройки → «Импорт JSON» там → обновить страницу.
3. Программа при запуске запрашивает у браузера постоянное хранилище (`persist()`) — это снижает риск автоочистки, но не заменяет бэкапы.

## Синхронизация между устройствами

Синхронизация необязательна. Без неё приложение продолжает работать локально. Для облака нужен собственный проект Supabase:

1. Создай проект на **supabase.com**.
2. Открой **SQL Editor** в проекте и выполни содержимое файла `supabase/schema.sql`. Таблица защищена RLS: пользователь может читать и менять только собственную запись.
3. В Supabase открой **Project Settings → API** и скопируй **Project URL** и публичный **publishable/anon key**. Никогда не используй `service_role` key в браузере.
4. В **Authentication → URL Configuration** добавь адрес сайта в **Redirect URLs**: `https://arsenshmid.github.io/CapitalOS/`. Для локальной проверки добавь также `http://localhost:5173/CapitalOS/` и `http://127.0.0.1:5173/CapitalOS/`.
5. В Capital OS открой **Настройки → Синхронизация между устройствами**, введи URL и публичный ключ, сохрани подключение, затем создай аккаунт.
6. Подтверди email по ссылке из письма. Она вернёт тебя на тот адрес приложения, откуда была начата регистрация.
7. На втором устройстве введи те же URL и ключ и войди в тот же аккаунт. Облачная копия загрузится автоматически; новые изменения синхронизируются через интернет.

Первое устройство, создавшее аккаунт без облачной копии, загрузит в облако свою локальную базу. На следующем устройстве облачная версия заменит локальную копию. Если устройства изменяли данные отдельно и версии разошлись, приложение остановит синхронизацию и попросит выбрать одну версию; выбранная копия заменит другую целиком.

Supabase хранит финансовые данные проекта. Доступ к строкам ограничен аккаунтом, но данные не зашифрованы приложением отдельно от облачного сервиса. Продолжай регулярно скачивать резервные копии.

## Как расширять программу

Архитектура сделана так, чтобы наращивать функционал малой кровью.

**Добавить правило совместимости** — одна функция в массиве `COMPAT_RULES` (`src/engine/flip.ts`):

```ts
// пример: проверка «модулей RAM не больше слотов» уже есть;
// новое правило = новая стрелка в массив:
p => {
  if (!p.mb || !p.gpu) return null;
  if (p.gpu.widthSlots && p.mb.pcieSlots && p.gpu.widthSlots > p.mb.pcieSlots)
    return C('GPU↔MB', 'WARN', `Видеокарта занимает ${p.gpu.widthSlots} слота, на плате меньше`);
  return null;
},
```

Правило вернуло `null` → проверка не выполнялась (не хватает данных). Уровни: `OK` / `WARN` (🟡 — можно, с пометкой) / `FAIL` (🔴 — сборка заблокирована). Новое правило автоматически заработает в конфигураторе и в тестах.

**Добавить категорию расходов** — «Финансы» работают из коробки; для участия в «минимальном burn» пометь категорию `mandatory: true` в `src/db.ts`/seed.

**Планируемые модули** (архитектура готова, точки входа описаны в коде):
- шифрование базы паролем (`packages/vault` из полного ТЗ подключается без изменения движка);
- BTC-модуль: лоты, FIFO, живые курсы из 3 источников, симуляторы покупки/продажи, стресс-тесты;
- графики капитала (дневные снапшоты уже предусмотрены моделью данных);
- Build Optimizer — «какая сборка из склада даст максимум прибыли».

## Безопасность и приватность

- **Локальный режим:** данные хранятся в браузере устройства. **Облачный режим:** копия хранится в подключённом проекте Supabase и доступна только вошедшему пользователю благодаря RLS.
- **Не хранится и не запрашивается никогда:** seed-фразы, приватные ключи, банковские логины/пароли, 2FA-коды. В коде физически нет полей для них. Приложение — **watch-only** по отношению к BTC.
- **Сеть:** без облачной синхронизации приложение не отправляет финансовые данные. При включённой синхронизации данные передаются Supabase по HTTPS.
- **Телеметрия, аналитика, реклама:** отсутствуют.
- **Код открыт** — можно (и нужно) прочитать каждую строчку, которая считается с твоими деньгами.
- **Пароль Supabase не хранится приложением.** Восстанавливай его через Supabase и сохраняй резервные копии данных отдельно.

## Правовая модель

Программа хранит юридический статус активов **как факт** — для честного учёта, не для обхода:

- Счёт с пометкой «арестован» виден в балансе, но исключён из доступных денег, Safe-to-Spend и Runway — потому что распоряжаться им нельзя. Это отражение реальности, а не сокрытие.
- Обязательства «в процедуре» показываются в Net Worth (полный) номиналом, но не вмешиваются в ежедневный cash-flow — если текущий платёж по ним равен нулю.
- В коде нет и не будет функций сокрытия активов, дробления, маскировки происхождения средств.
- Экспорт JSON можно использовать как выгрузку для отчётности — программа прозрачна по построению.

## Решение проблем

| Симптом                                           | Причина и решение                                                                                                                                 |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ERR_CONNECTION_REFUSED` на localhost             | Сервер не запущен. Терминал → `cd` в папку проекта → `npm run dev` → открой адрес **из терминала**. Попробуй также `http://127.0.0.1:5173`        |
| `npm не является внутренней или внешней командой` | Node.js не установлен или терминал открыт до установки. Переустанови Node, **перезагрузи ПК**                                                     |
| `npm ERR! Missing script: "dev"`                  | `package.json` пустой/испорчен. Сверь файл с оригиналом посимвольно                                                                               |
| Белая пустая страница                             | Опечатка в коде. F12 в браузере → Console → там имя файла и причина                                                                               |
| Красные ошибки при `npm run dev`                  | В сообщении указаны `файл:строка` — сверить это место с оригиналом                                                                                |
| Данные пропали                                    | Браузер очистил хранилище или ты открыл другой браузер/устройство. Восстанови из последнего экспорта JSON. Экспорт — раз в неделю, без исключений |
| Демо загрузилось снова после сброса               | Используй «Настройки → Начать с чистого листа» (ставит флаг, что демо больше не нужно)                                                            |
| Порт 5173 занят                                   | Vite сам предложит 5174 — открывай адрес из терминала                                                                                             |

## FAQ

**Мои деньги утекут на GitHub?**  
Нет. GitHub хранит только код. Данные — в браузере твоего устройства и в файлах экспорта, которые ты сам куда-то положил.

**Почему «Вероятный поток» серым и не считается в «безопасно потратить»?**  
Потому что этих денег ещё нет. «Скорее всего продам ПК на 10 000» — это не деньги. Строка станет живой, когда ты нажмёшь «ПРОДАНО». Это защита от кассовых разрывов.

**Почему покупка деталей — не расход?**  
Деньги не исчезли — они стали товаром на складе. Расходом они станут, только если деталь испорчена/продана в убыток. Иначе месяцы закупок выглядели бы «убыточными», а месяцы продаж — «сказочными», и ты бы принимал решения по кривым цифрам.

**Почему после вывода денег из кассы капитал не изменился?**  
Потому что это не доход — деньги переехали из одного твоего кармана в другой. Доходом была прибыль в момент продажи.

**Можно пользоваться с телефона?**  
Да: опубликуй на GitHub Pages и открой ссылку с телефона. Но помни: у телефона — своё отдельное хранилище данных. Перенос — только через экспорт/импорт JSON.

**Программа что-нибудь посоветует?**  
Нет. И это принципиально. Она считает и показывает последствия. Решения — всегда твои.

**Это не финансовый совет?**  
Нет. Это инструмент учёта и моделирования. Никаких гарантий результатов никаких решений программа не даёт.
